# GripperForge — 制約

`requirements.md` の「制約」を補強し、実装時の意思決定基準を明文化する。

## 技術的制約

### 計算資源
- 単一マシン・単一プロセスで実行可能な規模に抑える
- メモリ：最適化実行時 4 GB 以内
- CPU 時間：1 ジョブあたり最大 10 分（実用想定は 1〜3 分）
- GPU は **前提としない**（将来拡張として保留）

### ライブラリ選定方針
- コア最適化エンジンは **純粋 Python + NumPy/SciPy** のみ（C 拡張を避ける、コード可読性優先）
- 外部 FEM ソルバー（FEniCS, Abaqus 等）は使わない
- 機械学習ライブラリ（PyTorch, TensorFlow）は初期バージョンでは使わない

### 数値的制約
- `penal` は 3.0 を既定、3.5 まで連続増大許容
- `rmin`（フィルタ半径）は 1.2〜2.5 要素長の範囲で調整
- 最大反復 `maxloop` は 200（収束しない場合は警告）
- 収束判定：密度変化の最大値 < 0.01

### プラットフォーム
- Python 3.11+ を一次ターゲット（3.10 も動作すべき）
- OS：Linux / macOS を優先、Windows は WSL2 で動作確認

## ビジネス・物理制約

### 試作コスト
- 1 品種あたり試作費 3,000〜10,000 円（TPU フィラメント + 印刷時間）
- Phase 4 の実ワーク検証全体で 10 万円以内

### 時間制約
- CAD アップロード → 設計完了：数時間以内が理想、MVP では手動でも可
- 全フェーズ合計期間：約 5 ヶ月（概ねプロジェクト Roadmap に準拠）

### 物理制約
- 3Dプリンタは FDM 方式 TPU 対応機を想定
- 印刷向き：サポート材不要な向きで STL 出力すること
- フィンガー最小厚：1.5 mm 以上（FDM の造形限界）
- 把持対象ワーク重量：初期は 500 g 以内

## 運用上の制約

### セキュリティ
- 顧客 CAD データは機密扱い。ログに形状データを出力しない
- Web UI 運用時は HTTPS 前提（MVP では localhost 実行で可）
- 個人情報は原則扱わない（顧客企業名・担当者名のみ）

### 知的財産・公開範囲
- OSS 公開する範囲：最適化エンジンコアのみ（顧客事例の定量データは除外）
- **ライセンス：MIT**（2026-04-10 確定、Phase 5 の公開時に適用）
- 顧客提供 CAD データは公開しない

### ドメイン知識の制約
- コンプライアントメカニズム設計において、過度な応力集中箇所を可視化すること
- 実ワーク検証では安全のため、把持失敗時にワークが落下しても被害が出ない環境で実施

## 制約の前提と検証
- 上記のうち太字化されていない数値は想定値であり、Phase 1 完了時点で実測と突き合わせて更新する
- 制約が厳しすぎて要件が満たせない場合、`requirements.md` の「成功条件」と併せてユーザに再確認する
